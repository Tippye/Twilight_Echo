# ASIO 爆音、卡顿与 Native DSD 修复（2026-10-15）

## 现场证据

- 本机日志在北京时间 13:07:08、13:07:59、13:09:19 记录了 `asio_helper_callback_stalled`，随后出现播放信息和可视化 RPC 超时。
- 官方 FiiO ASIO Driver，版本 1552，能力探测包含 DSD64、DSD128、DSD256；不能据 PCM 播放时的 Native DSD 状态判断硬件不支持。
- 项目 `resources/audio-engine` 中的旧辅助程序实际为协议 v1，与已经存在的 v4 源码/构建不同。修复后的引擎和辅助程序统一为协议 v5，必须一起部署。
- 使用最新源码的双缓冲实现，DSD256 / 2048 samples / 安全模式仍能复现真实断供：8 秒内辅助进程记录 9500 次欠载和 9500 次无法及时提交的回调。单独提高线程优先级没有解决。

## 原因和修复

1. 此驱动的 Native DSD 缓冲按 1-bit samples 计数。DSD256 的 2048 samples 仅约 0.181 ms；两个进程每块音频来回唤醒，无法稳定满足双缓冲的交接期限。
2. Native DSD 改用有界单生产者/单消费者队列。按真实驱动缓冲单位生成完整音频块，最多预备 32 块，正常目标约 8 ms；DSD256 / 2048 samples 受上限限制约 5.8 ms。队列保持源顺序并保留原有位序转换及保守缓冲边界。
3. 父进程音频工作线程注册 Windows MMCSS `Pro Audio`。系统服务不可用时回退到线程优先级提升，退出时恢复。
4. 辅助进程的真实回调、欠载和丢块计数并入诊断 JSON 及会话/累计统计。以驱动边界是否实际取到音频为准，移除隔离模式下基于父进程唤醒间隔的假欠载判断；源音频短读仍独立计数。
5. PCM 保留双缓冲路径，并使用相同的实时线程调度和真实欠载统计。

原始取证和复测记录位于本地 `work/asio-*.jsonl`、`work/asio-*.log`。短时静音测试验证传输连续性、计数和模式切换，不能替代真实音乐的听感复测或证明长时间播放永不受系统负载影响。
