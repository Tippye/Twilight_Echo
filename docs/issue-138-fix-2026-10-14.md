# #138 网易云 v1 播放地址修复（2026-10-14）

关联问题：<https://github.com/Px-asen/Twilight_Echo/issues/138>。

## 原因与修改

当前依赖 `@neteasecloudmusicapienhanced/api@4.35.1` 的 `song_url_v1`
默认使用 xeapi。没有缓存公钥时，实际请求实现抛出
`xeapi public key is missing`；网关将没有 `body` 的异常统一转换成
HTTP/API 404 `Not Found`，日志也没有保存 `Error.message`。
这条路径已通过真实依赖和 localhost 网关确定性复现。

内置网易云插件现在为 `/song/url/v1` 的每档音质显式传入
`crypto=eapi`。请求仍使用官方的 level 接口，保留歌曲 ID、FLAC 参数、
账号 Cookie、音质阶梯、取消、缓存与旧 bitrate 接口兼容回退。
它不需要 xeapi 公钥；有可用 v1 地址时不会触发旧接口。

通过现有 pnpm dependency patch 修改网关：内部异常返回 HTTP/API 502，
响应 `msg` 与日志 `message` 保存错误原因；真实上游的状态与响应体、
登录提示及 Cookie 行为继续沿用。原 QR 登录补丁保留。
锁文件已更新，离线 frozen 安装验证了补丁实际应用。

## 为什么没有直接补调 generateConfig()

`src/main/ncm/api.ts` 确实直接调用 `serveNcmApi()`，没有执行上游 CLI 的
`generateConfig()`。但当前上游实现先调用默认也使用 xeapi 的
`register_anonimous()`，随后才获取公钥，且捕获、吞掉这两个步骤的错误。
因此单纯补调初始化无法保证冷启动成功，还会引入额外启动网络请求。
本次在播放请求上使用依赖支持的 eapi 参数，同时补齐错误诊断。
没有修改其它接口的默认加密或整个 xeapi 初始化流程。

## 验证

- 新增插件回归在修改前失败；修复后自动、Hi-Res、无损、高、标准五种设置
  均通过首次 v1 请求取得地址，不依赖旧接口。
- `verify:ncm-patch` 包含实际安装依赖的 localhost 网关测试：使用真实
  song 模块和 eapi 加解密，只替换远程 HTTP 传输与临时凭据读取。
  覆盖四档音质参数、账号 Cookie、公钥异常原因、上游 404、登录与空异常。
- 真实匿名请求歌曲 `4939801`：hires、lossless、exhigh、standard 均返回
  HTTP/API 200，且各返回一个播放地址。前三档实际返回 exhigh，标准档
  返回 standard，说明实际音质仍由上游账号权限与曲目可用性决定。
  未使用用户登录凭据，也没有下载或播放歌曲。
- `pnpm run test:plugins`：503 项通过、1 项跳过；
  `pnpm run verify:ncm-patch`：7 项网关检查通过，原 QR 登录补丁有效。
- `pnpm run build`：主进程与界面类型检查、electron-vite 构建及 renderer
  资源预算检查通过；定向 ESLint 和 Prettier 检查通过。

## 复测

运行 `pnpm install --frozen-lockfile`、`pnpm run verify:ncm-patch` 和
`pnpm run build`，重新启动当前构建，登录网易云后连续切歌并检查请求。
应看到 `/song/url/v1` 带 `crypto=eapi` 并返回账号权限允许的地址。
真实没有地址时仍允许后续兼容回退，不应把兜底成功当成 v1 成功。
