# 内存排查与图片资源优化（2026-10-15）

## 观察与边界

- 用户截图中 Electron 进程组约 772 MB。
- 排查时运行的是项目的 Electron 43.5.0 实例。Windows 工作集采样约为：GPU 380 MiB、页面渲染进程 357 MiB、主进程 231 MiB。工作集包含共享页，不能直接相加后与任务管理器截图对比，也不是 JS 堆大小。
- 本机背景目录有一张 6676 × 3768 的 PNG，压缩后约 12.2 MiB，单份 RGBA 像素数据约 96 MiB。当前保存的背景配置是纯色，尚不能确认它是截图中高占用的原因。
- 项目已有列表虚拟化、封面缩略图、部分有界缓存、插件休眠和分析任务进程退出机制。本次不改播放链路和插件生命周期。

## 已实现

1. 背景图生成磁盘显示副本，最长边不超过 3840、像素数不超过 3840 × 2160；不放大小图，保留 PNG 透明度和磁盘原图。
2. 同图请求合并，不同图转换串行；跨启动复用显示副本，内存只保留最多 32 条路径。副本被清理后重新生成，转换失败回退原图。
3. 背景协议通过文件流返回内容，不再在主进程图片 LRU 中保留背景文件的完整 Buffer。显示 URL 增加版本参数，绕开旧的不可变浏览器缓存。
4. 其他协议图片缓存的字节预算由 64 MiB 降至 16 MiB，保留原有 LRU 和并发请求合并逻辑。

6676 × 3768 的图片显示副本为 3833 × 2163，单份 RGBA 数据约 31.6 MiB，比原图少约 64.3 MiB。这个数字仅是像素存储预算，不是整个应用的实测下降值。首次生成仍需解码原图，不能消除首次转换的内存峰值；超过 4K 预算的显示场景会使用缩小后的图片。

## 验证与后续测量

- `test:memory-assets` 覆盖尺寸预算、并发合并、原图保留、磁盘复用、失败重试、缓存清理及 Electron 原生图片透明度和流读取。
- 背景显示、主题缓存和外观配置回归测试通过；类型检查、修改文件 ESLint 和生产构建通过。
- 需在重新启动后，用相同窗口尺寸、页面、主题、播放状态比较稳定后的进程私有工作集；不要将构建或测试进程计入。
- 下一轮优先记录 GPU 纹理/合成层与渲染进程 JS 堆。`App.vue` 的 `streamingPageTabs` 会保留已访问的流媒体页；若堆快照证明它们占比高，可进一步设计闲置页面卸载与导航状态恢复。直接卸载会改变返回页面时的详情和滚动位置，需一并处理。

## 第二轮：只减少临时分配

- 液态玻璃位移/高光贴图原先通过 `createImageData` 再复制完整 RGBA 数组，现在让 `ImageData` 直接引用已有数组。尺寸预算不变，每次生成最多减少约 8 MiB 的临时像素副本；编码完成或失败后把临时 canvas 尺寸归零，及时释放画布存储。
- 歌单封面导入原先总会先读取 Base64，再读取 ArrayBuffer 交给主进程缓存。现在仅在没有缓存桥接的兼容路径读取 Base64。6 MiB 文件可避免生成约 8 MiB 字符的 Base64 内容，具体内存取决于 JS 引擎字符串表示。文件格式、尺寸验证和磁盘缩略图处理保持不变。
- 81 项相关测试通过，包含真实 Electron 中新旧贴图编码结果完全一致，以及歌单封面缓存路径不调用 Base64 读取、兼容路径仍可使用；Web 类型检查和修改文件 ESLint 通过。
- 本轮收益属于临时分配/峰值控制，尚无应用整体常驻内存下降的对照测量。页面卸载、播放缓冲、进程模型、玻璃采样分辨率均未调整。

## 第三轮：主题工作台素材

- 主题工作台的诊断缓存仍保留最多 128 个条目，但键改为短哈希，不再把完整 Base64 数据 URL 复制到 Map 键中；哈希按素材类型和内容计算，素材对象用 `WeakMap` 记住结果。
- 诊断用的临时 `Image` 在完成或超时后立即解除事件和图片源；素材卡片图片使用浏览器懒加载与异步解码，减少打开工作台时一次性解码屏幕外原图。
- 主题工作台全套回归共 31 项通过，包含 Electron 行为和 SFC 编译检查；Web 类型检查和 ESLint 通过。

## 第四轮：临时图像解码释放

- 主色提取和平均色提取完成或失败后会解除 `Image` 事件并清空 `src`，解除临时图片对资源的引用；清理在调用方恢复执行前完成，取色算法不变。
- 液态玻璃环境采样完成后或返回的图片已过期时会清空 `src`，解除仅用于取样的图片引用。
- 20 项颜色、环境和采样加载回归通过，Web 类型检查、ESLint 和格式检查通过。

## 第五轮：主题资源预热

- 主题资源预热会等待图片解码完成，但临时 `Image` 在成功或失败后都会解除回调并清空 `src`；主题样式继续使用原 URL，解除预热图片对资源的引用。
- 主题 token 化回归和性能测试共 23 项通过，Web 类型检查、ESLint 和格式检查通过。

## 第六轮：背景编辑器临时图片

- 背景导入的验证图片在 `decode()` 后立即清理事件和 `src`；透明配方取样完成或请求过期时也释放采样图片。用户保存的背景 URL 不变。
- 背景编辑器 Electron 行为回归 2 项通过，Web 类型检查、ESLint 和格式检查通过。

## 第七轮：主题素材尺寸探测

- 素材卡片读取图片尺寸的临时 `Image` 现在会在素材切换、成功、失败和组件卸载时解除回调并清空 `src`，取消旧素材探测并解除资源引用。
- 主题工作台 31 项回归通过，Web 类型检查、ESLint 和格式检查通过。

## 新发现与收益边界

- 上述清理不强制驱逐 Chromium 的图片缓存，也不保证立即降低进程工作集；已完成的、不可达的图片原先也可能由 GC 回收。本次保证的是临时对象在使用完成后不再保留图片源，尚无整个应用常驻内存下降的对照测量。
- 素材卡片的懒加载只作用于显示图片；尺寸探测和诊断仍会读取素材，不能据此声称打开工作台时完全不会解码屏幕外图片。
- `libraryMetadataEnrichment.ts` 的 `failures` Map 在查询失败时插入，仅在同查询成功后删除；离线扫描大量不同曲目可能长期保留查询字符串和退避状态。可在后续设计过期清理或条目预算，但需保证尚未到期的查询不会过早重试，本轮未改。
- `useAppNoticeStore.ts` 的通知历史达到 50 条后只淘汰无操作按钮的记录；全部记录都带操作按钮时仍可继续增长，回调还可能捕获业务对象。强行限制会删除可执行操作，应先明确保留策略并测量回调持有量，本轮未改。
- 已访问流媒体页面的常驻状态仍是优先测量对象。需要对相同页面访问序列比较 JS 堆、DOM、图片资源和进程私有工作集，再决定是否实施闲置页面卸载。
