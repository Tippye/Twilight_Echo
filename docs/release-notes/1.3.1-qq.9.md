# 1.3.1-qq.9

修复 QQ 音乐高音质取流、保留进度切换音质，以及暂停或自然播完后定位恢复的完成时序。

- 分离网络并发和有界压缩数据预读；只对尚未发布的未来块做有限网络重试。大 Range 可先返回已校验的逻辑元数据，避免旧 reader 占满额度时阻塞新连接握手。
- HTTP 首次打开、探测和定位共享启动预算；运行中定位分别限制无字节进展和总时间。下一首准备异步执行，当前歌曲启动不等待下一首网络。
- 实际 IPC seek handler 等待异步定位完成，renderer 再读取当前源并提交确认位置，修复后退定位被旧位置覆盖的问题。自然 EOF 后在慢定位中实际准备音源；手动停止仍保留明确的失败语义。
- 缺少首选音质时沿同一歌曲使用可用音源，HiFi 面板显示实际源参数。

本轮真实验证包括《One Last Kiss》单首队列、Hi-Res/FLAC 非零位置切换和实际96/48kHz、24-bit，普通暂停定位及自然 EOF 后定位恢复；《素直未満》在 Hi-Res 不可用时播放实际 FLAC48kHz/24-bit，所取样本未重新进入加载。新进程保留会话和 FLAC 偏好，无需再次扫码，正常播放后退出。

400项定点源码回归、11项独立实际调用链验证及产物审计通过。8项原生门禁由字节完全相同的原生文件及未变源码继承，未因 IPC 修改重跑。安装包175项文件与成品目录逐字节一致；rc.8插件34成员CRC、32模块闭包通过。

验证不代表感知上绝对无卡顿。普通/EOF定位到恢复请求的间隔分别为7.558/21.514秒，不能称为立即恢复或纯原生定位耗时。冷启动证明会话可用，音频缓存命中未知；早期百秒对照两版均稳定，没有首播加速证据。有界预读不保证任意歌曲都有20秒领先，尚未证明或接入 QQ P2P 加速。

两次启动前及冷播放后观测到原 QQ 音乐进程族为0，普通媒体播放可独立运行；已有可选本地臻品效果仍保留其组件依赖。本次不包含另一会话 c99/1d35 的独立音效实现，不分发 QQ DLL 或模型。
