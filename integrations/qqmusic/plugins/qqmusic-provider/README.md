# QQ 音乐 Windows 音源

将 Windows QQ 音乐 22.71 的请求、登录和媒体变换接入 Twilight Echo。Provider ID 为 `qq`，插件 ID 为 `com.twilightecho.provider.qqmusic`。

当前 Windows 构建需要本项目的 Twilight Echo **1.3.1-qq.10 或更新兼容构建**，包含 QQ 官方登录桥、不可播放曲目的通用状态支持、逐曲音质选择、真实播放元数据和音质解析终止。旧上游 1.3.0 不包含这些接口；插件会拒绝在缺少登录桥的宿主中启动。

## 已接入的功能

- 歌曲、歌手、专辑和歌单搜索；保存歌曲 MID 与数字 ID，重启后可重新取得媒体地址。
- 手机 QQ 官方扫码登录；安全验证在官方窗口完成，登录状态由服务端校验。
- 当前账号创建和收藏的歌单、我喜欢的歌曲与播放器喜欢按钮；支持读取喜欢状态、添加和取消喜欢。完整歌单使用宿主虚拟列表，不以本地分页截断数据。
- 歌手热门歌曲、简介与完整专辑列表；专辑曲目可直接加入播放队列。
- 每日30首、最新发行歌曲预览、推荐歌单；公共歌单以详情接口验证的身份打开。
- 发现歌单、完整普通分类和前后分页；同名分类在标签中注明分组。
- 明文同步 LRC 歌词、歌曲与专辑元数据。
- MP3 128／320、FLAC、Hi-Res、杜比、5.1、臻品母带与臻品全景声八项选择；实际音源仍由每曲资料和当前账号验证。
- 插件私有本地音频代理、随机读取、有限并行分段与内容解密；Twilight 原有音频引擎负责标准媒体解码和设备输出。
- 命名队列恢复；开启宿主恢复设置后，支持正常退出、重启和进度续播。

歌手接口采用目标客户端配置所指向的官方内嵌页面请求形状，经当前 Windows ct19／cv2271 通道实测接受；这部分不是原生 C++ 请求构造函数的证明。Windows 入口不使用保留的旧 Android profile。

## 使用

1. 启动本项目的兼容 Twilight 构建，在扩展中心安装正常 Windows 插件包并启用 QQ 音乐。
2. 点击 QQ 音乐登录，用手机 QQ 扫码并确认。如出现验证，在官方窗口操作。
3. 在搜索音源中选择 QQ 音乐；流媒体音乐的“我的音乐库”展示当前 QQ 账号歌单。
4. 播放 QQ 音乐歌曲时，在**播放条右侧的“音质”下拉按钮**选择品质。列表读取当前歌曲的音质资料，明确未提供的选项会禁用，资料不足的选项标注待验证；有格式记录仍需当前账号取得实际地址。播放器会重新取得当前歌曲地址，保留进度和播放／暂停状态。首选音质缺源或服务端明确拒绝该档位时，插件会在同一歌曲记录内尝试较低音质：杜比或5.1依次尝试 Hi-Res、FLAC、320、128；普通档只向下尝试，每档最多一次。首选设置保留，全部失败则停止并提示，不搜索或替换成同名歌曲。登录、网络及格式验证错误直接提示。这里显示首选音质，播放页与 HiFi 展示实际解码格式、采样率等信息；播放页文件大小来自当前已解析音频的明文长度，未知时显示为空。也可在**设置 → 系统与关于 → 插件设置 → QQ 音乐播放音质 → 打开设置**保存，下次播放应用。
5. 如需启动时恢复队列，在播放设置开启“启动时恢复播放”。默认关闭，恢复后需手动点击播放。

臻品母带、臻品全景声分别使用该歌曲的对应网络媒体音源；不可用时在同一记录降到普通音质。该路径与本地音效不同；本插件不再提供 QQ 组件上的本地臻品处理，不请求本地音效的会员能力，也不发送 effect 标记。旧 excellent／excellentSpatial 首选项首次读取时在既有设置队列中迁移为标准128，后续读取不重复写入。第三方包不附带 QQ 的 DLL 或模型。

登录数据由宿主私有设置存储保护；当前任务构建使用 aes-256-gcm-machine 路径，不宣称 DPAPI。停用或退出登录会撤销音频代理及宿主媒体授权。正常包不包含账号数据、研究采集器、原 QQ DLL 或诊断入口。

## 实际验证与限制

MP3 128／320、FLAC、Hi-Res 96 kHz／24 bit 已取得真实音频并播放。杜比样本为 EAC3 48 kHz／6 声道，获取、解密、播放、seek 和暂停恢复通过；当前引擎解码输出为双声道，空间渲染尚未验证。5.1 选项有目标格式映射，但尚未找到取得成功的 DTS 样本。

臻品母带样本已取得192kHz／24bit FLAC，臻品全景声样本为48kHz／24bit FLAC；这不等于已验证空间扬声器输出。本轮保留的是这些实际网络媒体格式，本地臻品处理实现已退役。

Hi-Res 使用同一授权音源的有界并行 Range，并按该记录的文件长度与时长提前读取约 20 秒，单响应保留 2–8 MiB 压缩数据；时长未知时保留 2 MiB。参与该分段流程的请求限制为每响应 4 个、全局 8 个；全局压缩块额度为 16 MiB，这不是整个进程或所有网络连接的内存上限。首块立即输出，不等待预读填满。没有引入 P2P 服务或持久媒体缓存，也不要求原版 QQ 音乐进程运行。

尚未输出的后续块遇到已分类的临时网络错误时，可在原期限内重试一次，保持同一授权身份和 Range；已经输出的字节不重放，权限、完整性和取消错误不重试。较大的 partial Range 会先完成会话、身份与已知过期检查，再发送并刷新已验证媒体长度的 206 响应头，使解码器可关闭旧连接、归还预读空间；这只是元数据握手，媒体仍须通过上游 Range、长度和编码验证后才输出。后续上游失败会中止响应，206 本身不代表音频可播放。

建议配合 Twilight Echo 1.3.1-qq.10 使用：下一首准备在后台进行；网络跳转允许有字节进展的多轮定位，连续 5 秒无进展取消、整次最多 15 秒，初始打开、探测与定位共享启动预算；界面在原生确认后同步实际位置。实际播放仍受网络连续供给和曲目码率影响，平均下载速度高于码率也可能发生短时断流。

部分原生 type21 记录没有歌曲 MID 与媒体 MID，当前显示明确不可播放原因，保留元数据并从播放队列排除；这不表示歌曲被删除或账号无权限。增强逐字歌词与其他未取得实际媒体样本的专有编码没有验收通过。

每日推荐30首、最新发行20首、12张推荐歌单已通过真实 SDK 和界面验证；日语分类的前两页各30张、无重复，打开歌单后的播放通过。发现页保持服务端顺序；未启用热门／最新排序切换，也未接入 AI 歌单分类。服务端没有提供广场总数时，界面只显示当前页和前后翻页。歌手专辑列表暂未构造封面 URL，因为实际接口未返回直接的 albumPic 字段。
